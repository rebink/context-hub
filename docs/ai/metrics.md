# Success metrics and launch-acceptance measurement

Status: **LOCAL MEASUREMENT CONTRACT IMPLEMENTED; PRODUCTION MEASUREMENT AND LAUNCH REMAIN BLOCKED**

Synthetic/local baselines are not production measurements, do not establish an SLA, and cannot close a live gate. `npm run audit:metrics` emits the machine-readable latest local sample with environment and sample sizes. The exact executable registry is `scripts/metrics-registry.mts`; this document is its human-readable contract.

## Source decision

1. **Existing D1 immutable metadata/audit:** derive only project-scoped graph terminal outcomes/duration, accepted sync outcomes, snapshot outcomes, activity coverage, team/artifact event counts, and D1-known bytes for referenced immutable artifact/selected graph/snapshot-manifest objects. `GET /projects/:id/metrics?windowDays=7|30|90` uses direct current project membership, including archived projects, and three bounded project-predicated aggregate queries. All direct roles may read it because they can already read the underlying project Activity and metadata; restricting it to ADMIN would create a new role distinction without reducing content exposure.
2. **Response-local:** Context Engine returns exact fixed-point serialized `byteSize`, exact `sourceCount`, and the existing deterministic UTF-8-bytes/4 `tokenEstimate`. Graph/artifact response sizes can be measured at serialization without persistence. No tracking side effect is added.
3. **Cloudflare/GitHub analytics:** Worker requests/errors/latency, D1 billed rows/operations, actual R2 billing/inventory/operations, and Actions minutes are not D1 facts. They remain `BLOCKED_LIVE` until redacted provider aggregate receipts exist for the same account period. D1-known bytes are never labeled actual billed R2 storage.
4. **Manual study:** relevance and developer-experience outcomes require consent and a task rubric. Clipboard, query, content, and keystroke instrumentation is prohibited.

No raw telemetry table or migration is added. Never collect or log query/artifact/graph content, source paths, credentials, cookies, provider payloads, IP/user-agent, emails, or arbitrary labels. Allowed dimensions are finite enums/bands only. Project IDs occur only as authorization scope in the project route, not as exported metric dimensions; user identity is never returned.

## Exact registry

Common status values are exactly `MEASURED_LOCAL | DERIVABLE | BLOCKED_LIVE | MANUAL_STUDY | NOT_COLLECTED`. Rates return `null`, never zero, when the denominator is zero. Every D1 project metric window is the exact half-open UTC interval `[from,to)` (`from <= terminal/event timestamp < to`); provider receipts must state their own boundary without being merged into D1-derived values.

## Project metrics API

`GET /projects/:id/metrics?windowDays=7|30|90` returns the exact requested UTC window, current project status/role, audit coverage and sample counts, graph/sync/snapshot outcome arithmetic, graph duration samples, bounded activity counts, and all-time D1-known referenced immutable bytes. Empty samples return `rate: null` and timing values `null`. `artifactConflictRate`, `apiErrors`, and `failedUpdatePreservation` are explicitly `null` because the route cannot derive them honestly. Orphan bytes and actual billed R2 storage are also `null`.

The route performs authentication in the main router, then resolves direct membership before any aggregate. Every source subquery contains `project_id=?`; outsiders receive the same `404` and no aggregate query runs. Archived direct members retain access, matching Activity semantics. No names, paths, actor IDs, credentials, content, queries, storage keys, or arbitrary metadata are returned. The API is the minimum useful in-product surface. No Metrics navigation/UI is added: the complete launch view necessarily combines Cloudflare/GitHub account analytics and manual-study receipts that the browser cannot truthfully obtain, while project members already have Overview and Activity. A partial dashboard would invite false production/free-tier claims.

## Acceptance rule

Local acceptance requires the metrics audit, Context exact-accounting tests, route authorization/nonleakage/bounds/arithmetic tests, E2E, token/free-tier/architecture/deployment-offline checks, migrations, targeted tests, typechecks, builds, Biome, docs and secrets checks. Overall launch still requires live receipts and manual studies with stated sample sizes. A missing value is `null`/blocked, never estimated from unrelated metadata. Phase 6's contemporaneous final review and root gate were later recovered; its historical review topology and absent focused Git phase checkpoint remain independently blocked and are not recreated by this phase.
